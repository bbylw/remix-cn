设计原则

六大核心原则

在开发 Remix 3 的过程中，我们遵循以下原则。这些原则不是空话——它们直接体现在每一行代码和每一个包的边界划分中。

01

模型优先开发

AI 从根本上改变了人机交互模式。为 LLM 优化源代码、文档、工具和抽象层。 同时，为应用开发可在产品本身中使用模型的抽象，而不仅仅是把模型当作开发工具。

LLM 友好 AI 原生 上下文优化
02

构建于 Web API 之上

在整个技术栈中共享抽象层，减少上下文切换消耗。Web API 和 JavaScript 是唯一的全栈生态系统。

03

彻底运行时化

为打包器/编译器做设计会导致糟糕的 API 设计。所有包按"不依赖静态分析"的前提设计，测试无需打包即可运行。

04

避免依赖

依赖会把你锁定在别人的路线图上。明智选择依赖，完全封装，预期最终用自有包替换。目标是零依赖。

05

主张组合

抽象层应当单一用途且可替换。每个包独立使用且有文档。新功能首先尝试作为新包实现。紧密耦合的模块才放入同一包。

06

保持内聚地分发

极度可组合的生态系统很难学习和使用。Remix 将以单一的 remix 包进行分发，无论分发还是文档都如此。

单一入口 npm install remix
所有包统一在 remix 伞下，一个包搞定一切

面向未来的代码

Remix 的代码默认就是可移植的。在服务器端 Web API 可用时，我们加以利用——这意味着代码不仅可复用，而且面向未来。

每个包的承诺

组成 Remix 的所有包本身也都应该可以独立使用。这迫使我们考虑包边界，并帮助定义可移植、可互操作的公共接口。

  • 具有单一职责——每个包只做一件事
  • 优先采用 Web 标准，确保在各 JavaScript 运行时之间的最大互操作性
  • 标准缺失处，以不打断原有使用的方式增强，将不兼容风险降到最低

1
安装 Remix
$ npm install remix@next
$ pnpm add remix@next
$ bun add remix@next
2

3

npm run dev

体验最前沿的预览构建

我们也会将最新的 main 分支构建到 preview/main 分支，可用 pnpm（9+）直接安装：

# 安装完整 Remix
$ pnpm install "remix-run/remix#preview/main&path:packages/remix"
# 或只安装单个包
$ pnpm install "remix-run/remix#preview/main&path:packages/fetch-router"
